# النشر وGoogle Play — Math Clash

## الصورة الكاملة

```
جوال اللاعب (تطبيق Google Play = غلاف TWA لموقع اللعبة)
        │  HTTPS + WebSocket
        ▼
خادمك (Docker):  Caddy (HTTPS تلقائي)  →  خادم Math Clash (Node 22)
                                          ├─ ملفات اللعبة (public/)
                                          ├─ REST API + WebSocket (/ws)
                                          ├─ لوحة الإدارة (/admin)
                                          └─ SQLite على قرص دائم (/data)
```

### لماذا خادم خاص وليس «خادم ألعاب جوجل»؟
خدمة **Google Play Games Services** توفّر تسجيل الدخول ولوحات صدارة وإنجازات وحفظًا سحابيًا، لكن:
- **أوقفت جوجل واجهة اللعب الجماعي المباشر (الغرف والمباريات) عام 2020** — فلا يمكن بناء الغرف والمباريات السريعة عليها.
- لا توفّر لوحة إدارة لبطولات المناسبات والمواسم، ولا تتحقق من عدالة النتائج.

لذلك يأتي المشروع بخادمه الخاص الذي يقدّم كل ذلك. يمكن لاحقًا (اختياريًا) ربط لوحات صدارة Play Games عبر غلاف أصلي، لكنه غير ضروري.

## ١) تشغيل الخادم

### محليًا للتجربة
```bash
npm install
npm run dev            # http://localhost:8080 ، لوحة الإدارة: http://localhost:8080/admin
```
رمز الإدارة في وضع التطوير: `dev-admin-token-please-change`.

### الإنتاج على Google Cloud (موصى به: Compute Engine)
1. أنشئ جهازًا افتراضيًا **e2-small** (Ubuntu أو Debian) واسمح بمنفذي **80 و443** في الجدار الناري.
2. ثبّت Docker: `curl -fsSL https://get.docker.com | sh`
3. احجز نطاقًا ووجّه سجل **A** إلى عنوان الجهاز (مثلًا `play.yourdomain.com`).
4. على الجهاز:
   ```bash
   git clone <مستودعك> mathclash && cd mathclash/deploy
   cp .env.example .env      # عدّل DOMAIN و ADMIN_TOKEN (openssl rand -hex 24)
   docker compose up -d --build
   ```
5. افتح `https://النطاق` للعبة و`https://النطاق/admin` للوحة الإدارة.

**البيانات** في القرص الدائم `gamedata` (ملف SQLite). للنسخ الاحتياطي:
`docker compose cp game:/data/mathclash.db ./backup-$(date +%F).db` — أو فعّل لقطات القرص اليومية في Google Cloud (Snapshot schedule).

> **لماذا ليس Cloud Run؟** يعمل Cloud Run بلا قرص دائم، وقاعدة SQLite تحتاج قرصًا دائمًا وخادمًا واحدًا. على Cloud Run يلزم استبدال SQLite بـ Firestore/Cloud SQL (تعديل `server/db.js` و`server/services.js`). الجهاز الافتراضي أبسط وأرخص لهذا الحجم.

### متغيرات البيئة
| المتغير | الوصف |
|---|---|
| `ADMIN_TOKEN` | رمز لوحة الإدارة (12 حرفًا على الأقل، يفضّل 48 عشوائيًا). بدونه تتعطل لوحة الإدارة. |
| `DB_PATH` | مسار قاعدة البيانات (افتراضي `./data/mathclash.db`) |
| `PORT` | المنفذ (افتراضي 8080) |
| `CORS_ORIGINS` | فقط إن استضفت ملفات اللعبة على نطاق مختلف عن الخادم (مفصولة بفواصل) |

إن استضفت ملفات `public/` على نطاق آخر (مثل Cloudflare Pages) والخادم على نطاق مختلف، ضع في `index.html`:
`<meta name="mc-server" content="https://api.yourdomain.com">` وأضف `connect-src` للنطاق في سياسة المحتوى. **الأبسط: خادم واحد يخدم الاثنين.**

## ٢) لوحة الإدارة (لك وحدك)

`https://النطاق/admin` ← أدخل `ADMIN_TOKEN`.

- **البطولات**: اختر المناسبة (رمضان، العيد، اليوم الوطني، يوم التأسيس، الصيف، العودة للمدارس، الشتاء، العام الجديد، أو مخصّصة) فتُملأ الأيقونة واللون والاسم تلقائيًا. حدّد البداية والنهاية (أو اختصار: الآن 3 أيام، أسبوع، الجمعة…)، والنمط (عاصفة بوقت أو بقاء)، والصعوبة، وعدد المحاولات، و«نفس القطرات للجميع»، والجائزة لأفضل N.
  - تظهر البطولة تلقائيًا للاعبين عند موعدها في الرئيسية وصفحة الأونلاين، وتختفي بعد انتهائها.
  - عند الانتهاء (أو «إنهاء الآن») تُمنح الجوائز تلقائيًا مرة واحدة وتظهر في «جوائزي».
  - يمكنك التعديل، التعطيل/التفعيل، الحذف، ومشاهدة الترتيب.
- **المواسم**: «ابدأ موسمًا جديدًا» يبدأ تصنيف المباريات السريعة من جديد (1000) — مناسب لكل فصل أو مناسبة.
- **الإعلانات**: رسالة تظهر لكل اللاعبين أعلى الرئيسية والأونلاين.
- **اللاعبون**: بحث، تغيير اسم مسيء، إيقاف/رفع إيقاف.

## ٣) النشر على Google Play (تطبيق TWA)

اللعبة تطبيق ويب تقدّمي (PWA)، وأسهل وأرسمي طريقة لنشرها على Google Play هي **Trusted Web Activity** عبر أداة جوجل **Bubblewrap**:

```bash
npm i -g @bubblewrap/cli
bubblewrap init --manifest https://play.yourdomain.com/manifest.webmanifest
#   Application ID مثل: app.mathclash.twa  ،  اسم التطبيق: Math Clash
bubblewrap build          # ينتج app-release-bundle.aab و app-release-signed.apk
```
(تحتاج Java JDK 17 وAndroid SDK — يعرض Bubblewrap تنزيلهما تلقائيًا.)

### ربط النطاق بالتطبيق (Digital Asset Links) — ضروري لإخفاء شريط المتصفح
1. بعد `bubblewrap build` اعرض البصمة: `bubblewrap fingerprint` (أو من Play Console ← App integrity ← App signing key SHA-256).
2. أنشئ الملف `public/.well-known/assetlinks.json` من القالب `docs/assetlinks.example.json` وضع اسم الحزمة والبصمة، ثم أعد النشر.
3. تحقّق: `https://play.yourdomain.com/.well-known/assetlinks.json`

### Play Console
- ارفع ملف **AAB** في مسار الاختبار الداخلي أولًا ثم الإنتاج.
- **سياسة الخصوصية**: الرابط `https://play.yourdomain.com/privacy.html` (ضع بريد التواصل داخله قبل النشر).
- **حذف الحساب** (إلزامي في Play للتطبيقات التي تنشئ حسابات): متوفر داخل اللعبة (أونلاين ← حذف حسابي الأونلاين) — اذكر ذلك في نموذج «Data safety» واذكر رابط الصفحة.
- **نموذج Data safety**: البيانات المجمّعة = اسم مستعار، معرّف عشوائي، نتائج اللعب، قائمة الأصدقاء. لا موقع، لا جهات اتصال، لا إعلانات. مشفّرة أثناء النقل (HTTPS). قابلة للحذف.
- **الفئة العمرية**: إن استهدفت الأطفال فسيطبّق برنامج **Families**: اللعبة لا تحتوي إعلانات أو دردشة مفتوحة، والتفاعل برموز جاهزة فقط، والأسماء مُفلترة ويمكنك إيقاف أي اسم من لوحة الإدارة.
- **التصنيف المحتوى (IARC)**: اختر «Educational / Puzzle»، بلا عنف أو مقامرة.

### التحديثات
تحديث الموقع على الخادم يصل لكل اللاعبين فورًا دون رفع نسخة جديدة على Play (عامل الخدمة يجلب الإصدار الجديد). شغّل `npm run build:sw` قبل كل نشر.

## ٤) ما يجب معرفته
- **الأمان**: كل نتيجة أونلاين يعيد الخادم حسابها من سجل الإدخال على المحرّك نفسه؛ والجولات الأسرع من الزمن الحقيقي أو بسرعة استجابة غير بشرية تُستبعد من الترتيب. لا يمكن منع «برنامج آلي ذكي يلعب بسرعة بشرية» بنسبة 100% — لذلك تملك في اللوحة أداة الإيقاف.
- **السعة**: خادم واحد e2-small يكفي لآلاف اللاعبين يوميًا. عند النمو الكبير يلزم نقل القاعدة إلى Postgres وتوزيع الغرف.
- **النسخ الاحتياطي**: فعّل لقطات القرص اليومية في Google Cloud.
